# FANOVA Roadmap — 30-Day Delivery

Dates are relative to kickoff. Status is updated only after evidence is checked.

## P0 — Baseline and application mapping (Days 1–3)
- [ ] Read and map every official application question to evidence, answer owner, and status.
- [ ] Freeze core user story and one original-IP pilot scenario.
- [ ] Review relevant Soneium ecosystem products and competitors.
- [ ] Record unresolved risks and the token-plan requirement from the actual application form.
**Exit gate:** no major ambiguity about MVP, target user, or evidence required.

## P1 — Local vertical slice (Days 4–12)
- [ ] Establish web app and domain types.
- [ ] Creator publishes story plus explicit permissions.
- [ ] Fan submits contribution referencing source version.
- [ ] Creator can approve/reject; unauthorized approval fails.
- [ ] Add tests for the core workflow and failure path.
- [ ] Make UI states honest and understandable.
**Exit gate:** a fresh checkout can run the app and tests; one full local demo works.

## P2 — Soneium Minato proof (Days 13–19)
- [ ] Choose minimum contract surface based on evidence need.
- [ ] Write contract tests, including unauthorized call rejection.
- [ ] Deploy to Minato only after local tests pass.
- [ ] Verify source/address/chain ID and record deployment transaction.
- [ ] Connect the app to the contract or provide a clearly labelled explorer-backed proof panel.
**Exit gate:** an outsider can verify at least one relevant transaction/event.

## P3 — Pilot and differentiation (Days 20–24)
- [ ] Obtain permission to use original pilot story/materials.
- [ ] Run a small creator/fan test.
- [ ] Record real observations and user feedback; no invented metrics.
- [ ] Revisit competitor differentiation based on actual evidence.
**Exit gate:** honest pilot result, including negative or inconclusive findings.

## P4 — Application and demo (Days 25–30)
- [ ] Prepare answers mapped to every application question.
- [ ] Record a concise demo showing success and meaningful failure.
- [ ] Verify all addresses, links, tests, and status claims.
- [ ] Publish architecture, limitations, and reproducible setup.
- [ ] Perform outsider review of application and repository.
**Exit gate:** application is complete, evidence-backed, and internally consistent.

## Deferred / not in MVP
- Tradable FANOVA token deployment.
- Full royalty marketplace.
- AI generation suite.
- DAO/governance.
- Mainnet deployment.
- Multi-chain support.

Any item may move into scope only through the documented change-control process in `AGENTS.md` and `docs/PROJECT_SKELETON.md`.
